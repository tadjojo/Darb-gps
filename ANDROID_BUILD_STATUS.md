# Android build handoff — v8

- Added Linux/macOS and Windows PowerShell build scripts.
- Scripts generate the official Flutter Android runner only when absent.
- Required Android permissions are INTERNET, ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION.
- Tracking remains foreground-only; no background-location permission was added.
- Build script sequence: Flutter doctor, runner generation, manifest permissions, pub get, analyze, test, release APK build, APK existence check and SHA-256.
- Expected output: `mobile/build/app/outputs/flutter-apk/app-release.apk`.

## Current verification boundary

The scripts were reviewed and shell syntax checked, but not executed: this environment has no Flutter, Dart, Android SDK, or Gradle Android toolchain. Therefore no APK has been produced or device-tested by this run. First build requires dependency download and SDK license acceptance. Backend deployment and HTTPS configuration are separately required for real sign-in and live tracking. The mobile Dart source was not modified in this handoff.


## Phase 10 — Android foreground tracking source update

- Added Android `AndroidSettings` with a persistent foreground notification, wake-lock request, 5-second requested interval, and 5-metre distance filter.
- Added Android foreground-service permissions to the build scripts. The location service is started only from a visible app session, avoiding a broader background-location permission request in this phase.
- Tracking remains user-initiated and visible; no boot-start or covert tracking was added.
- iOS background tracking is explicitly not included in this phase.
- This change is source-level only: Flutter/Dart tooling and a real Android device were unavailable, so no compile or device test is claimed.
- See `mobile/docs/ANDROID_BACKGROUND_TRACKING.md` for limitations and the required test matrix.
